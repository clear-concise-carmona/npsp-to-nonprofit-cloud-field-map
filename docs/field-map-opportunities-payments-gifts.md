## Object-level mapping

**NPSP object(s):** `Opportunity (standard) + npe01__OppPayment__c (Payment, from the NPSP-managed package)`

NPSP tracks a donation as a standard Opportunity, with one or more child Payment records (npe01__OppPayment__c) representing scheduled or received installments against that Opportunity.

**Nonprofit Cloud object(s):** `GiftCommitment + GiftTransaction + GiftEntry + GiftBatch (Fundraising standard objects, API v59.0+)`

Nonprofit Cloud splits the same concept across several purpose-built objects: GiftCommitment (the donor's pledge/commitment), GiftTransaction (a completed transaction against that commitment), GiftEntry (pre-processing staging record with an audit trail), and GiftBatch (a batch of gifts being entered together).

**Relationship: Redesign required**

This is the second major structural change. A single Opportunity+Payment pair does not map to a single Nonprofit Cloud object - it maps to a small object graph. A one-time gift is roughly one GiftTransaction; a pledge or recurring commitment is a GiftCommitment with one or more associated GiftTransactions as installments post. There is no Salesforce-published field-for-field crosswalk for this change as of this map's last review - the entries below are built from the documented object/field purposes in Salesforce's own Nonprofit Cloud developer guide, not from a Salesforce migration tool output.

Sources: [source](https://developer.salesforce.com/docs/atlas.en-us.nonprofit_cloud.meta/nonprofit_cloud/npc_fundraising_api_objects_giftcommitment.htm); [source](https://developer.salesforce.com/docs/atlas.en-us.nonprofit_cloud.meta/nonprofit_cloud/npc_fundraising_api_objects_gifttransaction.htm); [source](https://developer.salesforce.com/docs/atlas.en-us.nonprofit_cloud.meta/nonprofit_cloud/npc_fundraising_standard_objects.htm); [source](https://www.dataimporter.io/blog/npsp-to-nonprofit-cloud-data-migration)

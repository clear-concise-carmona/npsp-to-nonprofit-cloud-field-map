## Object-level mapping

**NPSP object(s):** `npe03__Recurring_Donation__c (Enhanced Recurring Donations / RD2)`

NPSP kept the legacy object API name npe03__Recurring_Donation__c even after the 2021 "Enhanced Recurring Donations" (RD2) rebuild - RD2 is a behavior/field change on the same object, not a new object. RD2 added open-ended recurring donations, elastic/scheduled installment generation, and clearer status tracking.

**Nonprofit Cloud object(s):** `GiftCommitment + GiftCommitmentSchedule (Fundraising standard objects)`

Nonprofit Cloud has no single "Recurring Donation" object. A recurring gift is a GiftCommitment with a recurrence defined by GiftCommitmentSchedule, and each generated installment is a GiftTransaction.

**Relationship: Redesign required**

Practitioner-reported migration guidance (GoFundMe ProSupport, publishing on behalf of Salesforce.org/Salesforce Nonprofit Cloud integration docs) confirms recurring donations and their installment Opportunities are handled through a dedicated import/migration path rather than a direct field copy - see the official migration article linked below. Treat any field-level entry in this file as a starting point for validation against that guide, not a substitute for reading it directly.

Sources: [source](https://help.salesforce.com/s/articleView?id=sfdo.npsp_import_rd2_and_opps.htm&language=en_US&type=5); [source](https://prosupport.gofundme.com/hc/en-us/articles/37288736709659-Migrating-recurring-donations-with-the-Salesforce-Agentforce-Nonprofit-Cloud-NPC-integration); [source](https://ynexgen.com/blog/npsp-recurring-donations-vs-nonprofit-cloud); [source](https://developer.salesforce.com/docs/atlas.en-us.nonprofit_cloud.meta/nonprofit_cloud/npc_fundraising_api_objects_giftcommitment.htm)
